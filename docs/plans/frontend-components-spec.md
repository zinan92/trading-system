# Spec：前端组件化（/trade 拆成 React + TypeScript 组件）

状态：Park 2026-11-05 授权按商定顺序直接做（追平 tick-stock-panel 计划的第 1 步）。
跟踪：#1324（子 Issue #1325–#1330）。数据口径：2026-11-05 仓库实测。

## 1. 要解决什么

`/trade` 现在是一个 285KB 的单文件页面（`dashboard-gridmind.html`：内联脚本 245KB、约 254 个函数、样式 53KB），
上面再叠 5 个脚本（`gm-desk.js` 45KB、`gm-review.js`、`gm-backtest.js`、`gm-ai-sources.js`、`gm-desk.css`）。
每次改版只能「再叠一层」，改一处要在两套 DOM 之间对齐，测试只能用 node 跑纯函数。

目标：页面由带类型的组件组成，每个组件有自己的测试；最后 `/trade` 由一个 React 应用渲染，旧单文件页面退役。

## 2. 原则

- **一块一块换，每块单独上线。** 不做一次性重写。旧页面在全部换完之前一直能用。
- **只换展示，不换行为。** 每个组件调用的接口、请求体、按钮的启用条件与旧代码一致。
  下单相关的面板（预览、确认、控制）放到最后，请求体逐字节对齐旧代码并有测试锁住；
  确认下单仍只凭 Park 亲手按，组件化期间不新增任何下单或放行路径。
- **生产机器不需要 node。** 构建产物提交进仓库（固定文件名，交易台现有的内容哈希负责刷新缓存）；
  CI 重新构建并检查产物与源码一致。
- **行情不可信时不开新仓**、读不到就写读不到，这些现有语义原样保留。

## 3. 工具链

| 项 | 选择 |
|---|---|
| 位置 | `apps/web/`（独立 `package.json`，锁定精确版本，`package-lock.json` 入库） |
| 框架 | React 19.3.1 + TypeScript 7.0.2（strict） |
| 构建 | Vite 8.3.5 + `@vitejs/plugin-react` 6.1.2，库模式输出 `web.js` + `web.css` 到 `apps/trading-desk/src/trading_desk/static/web/` |
| 测试 | Vitest 4.1.12 + jsdom 30.1.3 + `@testing-library/react` 16.3.3 |
| CI | 新 make 目标 `test-web`：`npm ci`、类型检查、测试、构建，再 `git diff --exit-code` 检查产物没过期 |

## 4. 怎么接进现有页面（「岛」）

`web.js` 加到交易台注入的脚本里。它按元素 id 找「挂载点」，把对应组件渲染进去：

- 新组件替换某个旧叠加脚本时，旧脚本里那一段删掉，挂载点交给 React。
- 旧页面原生的面板（持仓表、K 线等）换的时候，在原位置放一个挂载点，原代码对应的渲染函数删掉。
- 组件之间共享的数据（当前品种、行情可信状态）放在一个小的 store 里，旧代码通过 `window` 上的事件读写，换完后删掉这层桥。

## 5. 顺序（每行一个 Issue / PR）

| # | 内容 | 风险 |
|---|---|---|
| 1 | 工具链 + CI；第一批岛：开仓前回测框、AI 依据、三件事 | 低：都是只读、已有测试 |
| 2 | 交易回看（`gm-review.js`，含 K 线图组件封装） | 低：只读 |
| 3 | 「今天」流程（判断、计划、新闻、AI 建议卡），即 `gm-desk.js` 的大部分 | 中：会写判断；不涉及下单 |
| 4 | GridMind 只读面板：顶栏、指标卡、持仓/委托/成交表、主 K 线 | 中：只读，但数据多 |
| 5 | 控制面板：品种选择、预览、确认、停止 | 高：下单相关，最后做，逐字节对齐 + 测试 |
| 6 | `/trade` 改由 React 应用整页渲染；`dashboard-gridmind.html` 退役 | 中：入口切换 |

## 6. 验收

- 每个 PR：组件测试 + 交易台测试全过；dev 上桌面和 375px 截图；生产部署后核对接口和页面。
- 第 6 步完成时：`/trade` 不再加载 `dashboard-gridmind.html`；所有面板都有组件测试；页面上的行为（包括按钮何时可按）与换之前一致。

## 7. 不做

- 不换设计语言（配色、布局保持现状；「做减法」是另一项工作）。
- 不加新功能；发现的旧问题记下来，另开 Issue。
- 不改后端接口，除非某个组件需要的数据旧页面是从 HTML 里抓的。
