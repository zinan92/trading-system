# Strategy Lab 前端设计规格（v1）

日期：2026-07-05
角色：UX/UI Designer（兼顾 PM 与 Trader 视角）
范围：Strategy Lab（研究回路）的前端信息架构与视觉方案；不改任何生产交易行为。
数据事实来源：`outputs/lab/registry.json`（102 次试验 / 39 个家族 / 87 valid / 15 invalid）、
`outputs/lab/reports/R1|R2|R3|E1–E4`、`outputs/lab/promotion/*.json`、`docs/strategy-lab-spec.md`。

---

## 1. 第一性原理：这个页面服务哪一个决策？

生产面板（指挥台）回答的是「**现在能不能交易**」。
Lab 页面必须回答另一个唯一的问题：

> **下一单位的研究注意力应该投给谁？**

一切元素只允许做三件事之一：

1. **排序**：按「扣费后的生存能力」给候选策略排序（筛选）；
2. **解释**：说清一个候选离晋级还差什么（选定 / 测试）；
3. **防自欺**：让多重检验、holdout 消耗、无效样本永远可见（科学纪律）。

不满足任何一条的信息，一律不上首屏。

**核心经济事实**（整个 Lab 的物理学）：每个策略最终都被压缩成一对数字——
`毛利 bp/趟` vs `每边成本 bp`。真实成本是 Binance USDⓈ-M maker 2bp / taker 5bp。
R1 扫描的 22 个想法里，**没有一个原始形态能活过 maker 2bp**；只有经过 R3
持仓几何优化后，2 个候选（psych_level_rejection、ema50_position）的保本费率
才被推过 maker 线。这就是首屏英雄图要一眼讲完的故事。

**研究 ≠ 生产（安全 UX）**：Lab 里的一切数字都不是实盘业绩。页面必须有
持续可见的「RESEARCH · 非实盘」模式标识，用紫色（--violet）作为研究模式
语义色，与生产页的四态语义色体系区分，防止研究数字被误读为生产数字。

## 2. 用户与节奏

单一用户（Park），两顶帽子，三种节奏：

| 帽子 | 节奏 | 要回答的问题 |
|---|---|---|
| PM | 30 秒 | 研究回路在收敛吗？漏斗里有几个活着的？下一步资源投给谁？ |
| Trader/Researcher | 5 分钟 | 这个候选的证据链完整吗？离 paper 还差哪几道闸门？ |
| 科学家（防自欺） | 常驻 | 这个数字被扫了多少次才出现的（N 次试验）？holdout 烧掉没有？ |

## 3. 四步流程 → 界面机制

用户指定的闭环：**筛选 → 选定 → 测试 → 归档**。映射如下：

| 流程步 | 界面机制 | 不是什么 |
|---|---|---|
| 1 筛选 | Lab 总览页：研究漏斗 + 「边际 vs 成本」排行榜（唯一英雄图） | 不是全指标海洋，不是权益曲线画廊 |
| 2 选定 | 候选详情（点击行进入）：成本曲线、几何热力图、晋级清单 | 不是原始 JSON 浏览器 |
| 3 测试 | 详情页内的「实验台」抽屉：模板化生成下一个实验（复制 CLI），登记后以 pending 状态回显 | v1 不在浏览器里执行计算 |
| 4 归档 | 「裁决」动作 + 墓地视图：每个家族有生命周期状态与裁决理由，死因可检索 | 不是删除，注册表永不删条目 |

**家族生命周期**（归档的状态机，UI 的一等公民）：

```
在研 active → 纸面候选 paper_eligible（通过全部闸门）
           → 搁置 parked（当前费率下无边际，留待条件变化）
           → 已否证 falsified（假设被证伪，记录死因）
不可回放 not_replayable（如 chan 系：历史信号有前视风险）单列
```

裁决动作写入 `outputs/lab/verdicts/{family}.json`（NEW，小型后端补充）：
`{stage, reason, decided_at, source_exp_id}`。墓地是功能不是垃圾桶——
它防止同一个死想法被重新测试。

## 4. 信息架构与布局方案

### 备选方案

- **A. v4 壳内新增顶级视图「研究 LAB」**（推荐）：与 指挥台/交易/回放/运维 并列。
  沿用既有导航心智与设计令牌；实现上按项目惯例可以是独立
  `dashboard-lab-v4.html`（与 replay 同模式），共享 v4 的 :root tokens。
- B. 完全独立的 lab.html 小站：自由度高，但复制品牌壳，割裂导航，长期两套壳漂移。
- C. 塞进指挥台的一个卡片：Lab 是一个工作流（四步闭环），不是一个状态；卡片装不下，
  且会污染「指挥台=生产决策」的定位。

**推荐 A**。理由：Lab 与 回放 同级——都是「证据工具」；导航一致性让
研究↔生产的跳转（如 lab_expectation 对照）成本最低。

### 页面结构（两层 + 一抽屉）

```
LAB 总览（筛选层）
├── 仪器状态条 instrument vitals（数据可信度先行，fail-closed）
├── 研究漏斗 research funnel（PM 30 秒答案）
├── 英雄图：保本费率 vs 真实费率（R1 基线 → R3 最优的位移）
├── 候选排行榜（表格，行点击进入详情）
├── 已归档 / 墓地（折叠区）
└── 既定结论 standing answers（E1–E4，折叠区）

候选详情（选定层，单家族）
├── 裁决头：生命周期状态 + 晋级阻塞项（白话）
├── 成本曲线图（0/0.5/1/2/5bp + maker/taker 参考线）——Lab 的「那张图」
├── R3 几何热力图（hold × scale，按 maker 净值着色，标注扫描 N=12）
├── 走查一致性（逐窗口正负 + regime 切片，有则显示）
├── 晋级清单（四道客观闸门 + holdout 一次性预算，逐项 ✓/✗）
├── 实验历史（该家族全部注册试验，含 invalid）
└── 动作条：⚗ 排队下一实验（抽屉） · 🏷 记录裁决（归档）

实验台抽屉（测试层）
├── 模板选择（R3 几何 / 成本网格 / regime 切片 / holdout 一次性射击）
├── 参数 diff 预览 + 该家族 N 次试验提醒（多重检验税）
└── 生成 CLI 命令（复制执行）；注册表出现 pending 行即回显
```

## 5. 展示什么（含数据可行性标注）

标注：**EXISTS**=数据已有；**DERIVE**=前端可从现有 JSON 推导；**NEW**=需小型后端补充。

### 5.1 仪器状态条（信任先行，排最上）

一行高密度 chips，任何一项异常即整页降级为琥珀色警示（fail-closed 的 UI 表达）：

- 数据覆盖：296,298 根 1m bar · 2025-12-11 → 今 · 缺口 0 —— EXISTS（coverage.json）
- 历史长度：205 天（<12 个月，覆盖基准=全量可用历史）—— EXISTS
- Holdout 预算：28 天隔离 · 已消耗家族 1/39（macd_baseline）—— DERIVE（registry 聚合）
- 注册表：102 试验 · 39 家族 · 15 invalid（invalid 数必须展示，这是诚实度指标）—— DERIVE
- 成本现实：maker 2bp / taker 5bp（VIP0）—— EXISTS（E4）

### 5.2 研究漏斗（PM 的 30 秒）

与指挥台「决策漏斗」同构（视觉语言复用）：

```
想法 22 → R1 有效 12 → 过粗筛(≥2bp/趟 & n≥100) 3 → R3 优化中 5 → holdout 已射击 1 → paper 0
```

全部 DERIVE 自 registry + reports。每级可点击 = 排行榜预置过滤器。

### 5.3 英雄图：保本费率 vs 真实费率

横向条图，x 轴 = 每边保本费率 bp（= 毛利/2）。每个家族两个记号：
R1 基线（空心）→ R3 最优单元（实心），中间位移线；参考竖线 maker 2bp、taker 5bp。
右过 maker 线 = 活着。实心记号旁必须挂「12 cells swept」的 N 角标（防 best-of-N 幻觉）。
—— EXISTS（R1/R3 summaries 全有）。

### 5.4 候选排行榜（每行一个家族）

默认只显示 valid、按 R3 最优 maker 净值降序。列（严格 8 列以内）：

| 列 | 来源 |
|---|---|
| 策略 + 周期 | EXISTS |
| 生命周期 chip（在研/候选/搁置/已否证） | NEW（verdicts） |
| OOS 笔数 | EXISTS |
| 毛利 bp/趟（R1 基线） | EXISTS |
| 保本 bp/边 → R3 最优 | EXISTS |
| maker 2bp 净值/笔（最优单元） | EXISTS |
| 最大回撤 / Sortino@2bp | EXISTS |
| 家族试验数 N（多重检验税，N≥12 亮琥珀） | DERIVE |

过滤器：周期 1m/5m · 状态（默认 valid，可开 invalid/not_replayable）· 生命周期。

### 5.5 候选详情（选定）

- **裁决头**：白话阻塞项。直接翻译 promotion blockers：
  `walkforward_objective_not_passed` → 「走查未过客观闸门」。—— EXISTS（promotion/*.json）
- **成本曲线**：expectancy/笔 在 {0, 0.5, 1, 2, 5}bp 的折线 + maker/taker 竖线 +
  保本点标注。—— EXISTS（cost_grid_results）
- **R3 热力图**：hold{1,2,4,8}× × scale{1,1.5,2}×，色阶=maker 净值，
  角标最佳单元与其样本数。—— EXISTS（r3_summary 家族 12 单元）
- **晋级清单**（Trader 的「还差什么」）：OOS≥100 ✓/✗ · 回撤≤上限 ✓/✗ ·
  成本+50% 仍为正 ✓/✗ · ≥2/3 regime 切片非负 ✓/✗ · holdout（一次性，已耗/未耗）。
  —— EXISTS（objective.gates + registry.holdout_consumed）
- **实验历史**：该家族全部注册条目（含 invalid 与原因），时间倒序。—— EXISTS
- **走查一致性**：逐窗口净值正负条（8 窗口）。—— EXISTS（windows 结果）

### 5.6 归档区（墓地）

折叠表：家族 · 死因（一句话）· 证据链接 · 裁决时间。
预填当前事实：chan 系 ×4 = 不可回放（历史信号前视风险）；grid、bollinger_reversion
= 负毛利已否证。—— 死因文本 EXISTS（R1 报告），状态字段 NEW（verdicts）。

### 5.7 既定结论（E1–E4 standing answers，折叠）

四行卡：E1 MACD 保本 0.217bp/边（死于真实费率）· E2 方向过滤在 3 天回溯样本上
减 alpha（-0.33/笔，样本太薄，结论悬置）· E3 可交易方向性 regime 占比 ~46% ·
E4 maker 限价比 taker 改善 +0.56/笔但仍为负。—— EXISTS（E 报告）。
价值：新实验的设计前提，防止重复提问。

## 6. 不展示什么（与理由）

这部分与「展示什么」同等重要：

1. **每个实验的权益曲线画廊** —— 小样本曲线是自欺的最强诱惑；曲线只在详情页
   按需展开，且必须与成本曲线同屏。
2. **指标海洋**（Sharpe/log-wealth/turnover/profit factor 全列）—— 排序只用
   maker 净值 + Sortino@2bp；其余进详情页的「全部指标」折叠表。指标越多，
   排序越随意。
3. **R2 特征重要性、校准分箱** —— 模型内部诊断，只属于 R2 详情页折叠区。
   R2 的结论（反推不如手写 top-3）用一行字呈现即可。
4. **走查窗口参数、spec_hash、原子写、文件路径** —— 仪器工程细节属于 OPS/
   代码，不属于研究决策界面。spec_hash 只在详情页页脚以小字提供（可复制）。
5. **实盘/纸面 P&L** —— 那是生产面板的职权。Lab 只在候选晋级后提供
   `lab_expectation` 对照入口（链接回生产页），绝不在 Lab 内混排生产业绩。
6. **可编辑的策略参数表单** —— v1 不做浏览器内自由调参。自由调参 UI =
   鼓励未注册的试验 = 直接违反「每次试验必登记」原则。只提供模板化实验
   （模板本身强制登记）。
7. **浏览器内触发计算** —— v1 只生成 CLI 命令。执行权留在终端，直到
   后端有带鉴权与排队的 run API（v2）。
8. **无效数据的静默隐藏** —— 反着来：invalid / insufficient_sample /
   not_replayable 必须可见（默认折叠但计数常显）。15 个 invalid 是纪律的
   证据，不是污点。

## 7. 防自欺 UX（Lab 独有的设计责任）

- **N 角标**：任何「最优」数字旁必须挂该家族试验数 N；N≥12 时角标变琥珀，
  hover 文案 = 「此数字是 N 次扫描中的最好值，含 best-of-N 抬升」。
- **Holdout 预算表**：holdout 是一次性弹药。仪器条常显「已消耗 1/39 家族」；
  详情页里 holdout 射击按钮带二次确认（「此家族只有一发」）。
- **Fail-closed 视觉**：数据缺口>0 或 coverage 状态非 valid 时，整页顶部
  降级为琥珀横幅，英雄图打上「数据不完整」水印——与生产页 RUN/DEGRADED
  语义一致。
- **研究水印**：顶栏常驻紫色「RESEARCH · 非实盘」chip；Lab 内所有金额
  一律以 bp 表达，不出现 $ 金额（$ 只属于生产页）。固定名义 $1,000/笔的
  研究口径在页脚注明。

## 8. 视觉语言

- 完全复用 v4 tokens：近黑 `#08090b`、发丝线 `rgba(255,255,255,.1)`、
  单一金色只给品牌、mono 数字、Bloomberg 密度、双语标签（中文主 + EN 小字）。
- **紫色 `--violet:#b894ff` = 研究模式语义色**（tokens 中已存在但生产页未占用）：
  LAB 导航徽标、生命周期 chip「在研」、实验 pending 状态。绿/红仍然只表达
  正/负边际，琥珀 = 纪律警示（N 税、数据降级），与生产页语义不冲突。
- 热力图色阶：负值向红、正值向青绿（teal），零点为中性表面色——与
  当日盈亏的红绿语义一致。
- 密度原则：首屏（1440×900）必须同时容纳仪器条、漏斗、英雄图、排行榜前 8 行。

## 9. 范围切割

**v1（本设计）**：只读渲染 + 两个轻写动作（记录裁决 verdicts、生成 CLI）。
后端仅需：`/api/lab`（聚合 registry/experiments/promotion/reports/coverage，
全部现成 JSON）+ `POST /api/lab/verdict`（写 verdicts/{family}.json）。

**v2（明确不做，防蔓延）**：浏览器内执行实验、自由参数搜索、多资产、
lab↔paper 自动对照面板、移动端。
