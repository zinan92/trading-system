# 人机双轨作战台 · 产品规格（V5 方向）

日期：2026-07-05
状态：方向已定，参数已锁；等机会普查 + 神谕网格实验结论后出 mockup。
背景：机器人定位从「多策略舰队」转为「现金流引擎」——短线利润喂长期持仓。
Strategy Lab 前端（strategy-lab-frontend-design.md）已搁置，Lab 后端作为验证仪器保留。

## 一句话定义

每天两场结构化的人机对照赛——周期开始前盲订作战单，盘中人机各跑一轨互不干扰，
周期结束后同一把尺子对账。

## 已锁定的参数（Park 2026-07-05 拍板）

1. **周期**：北京时间 09:00–21:00（DAY）与 21:00–09:00（NIGHT），每天 2 个周期
   （= UTC 01:00–13:00 / 13:00–01:00）。每周期一份作战单、一次对账。
2. **资金**：人轨、机器轨各 $10,000（纸面）。
3. **盘中机器轨对人保盲**：只显示机器轨当日 realized + unrealized PnL 两个数字；
   进出场点位、库存、网格状态一律收盘后揭示。

## 模块一 · 盲答作战单（每周期）

- 盲答问卷：方向（多/空/观望）、Range 上下限、关键位、失效条件、信心分。
  回答期间不展示任何 AI 观点。
- 提交即锁定（时间戳、不可修改），锁定后才揭示 Obsidian/AI 每日观点并排对照，
  高亮分歧。
- 生效优先级：人有输入 → 人的作战单驱动机器轨；截止无输入 → AI 作战单兜底；
  两者皆无（含 Obsidian 链路故障）→ 机器轨站下。Fail-closed。
- 副产品：人与 AI 各自的方向 track record 自动积累（方向命中率记分板的数据源）。

## 模块二 · 盘中双轨

- 实时行情：Binance WebSocket K 线流（正在形成的 K 线实时更新，1m/5m），
  浏览器可直连，TradingView 式体验。
- 机器轨：按作战单在 Range 内执行条件网格/分批；界面无暂停/干预按钮
  （干预只能走运维页）。盘中仅露出 realized / unrealized PnL（见参数 3）。
- 人轨：独立手动交易面板（方向、仓位档、止损止盈）、独立账本。
  双轨资金池隔离、互不可操作、成本口径一致。全程留痕（时间戳 + 可回放光标）。

## 模块三 · 周期对账

- 双轨记分卡：笔数、胜率、盈亏（bp 与 $）、捕获比（人 x/N vs 机 y/N，
  N 来自机会普查口径）、周期内最大回撤、纪律违规数（人轨超出自己作战单
  Range/方向的交易标红计数）。
- 作战单判卷：人与 AI 的方向判断分别对照实际走势打分 → 滚动命中率 vs
  神谕及格线。
- 一键回放：记分卡任一笔 → replay 页对应光标（现有 URL 参数机制）。
- 主数字用「月均日现金流」，当日为副（防按日发薪心理陷阱）。

## 实验依赖（先于前端）

- R5-A 机会普查：单向波段的数量/幅度/时长/周期分布 → 记分卡的「机会数 N」
  与现金流方程参数。初版 2026-07-05 已跑（scratch，正式化时入注册表）。
- R5-B 神谕夹逼条件网格：完美方向上限 / 随机方向下限 / 最低方向命中率及格线。
- 从即日起人与 AI 的方向判断开始留痕（模块一的数据先行，不等前端）。

## 不做（v1 边界）

- 不做盘中干预 UI、不做多资产、不做实盘（纸面先行，沿用 M 路线图闸门）、
  人轨不做自动化辅助（那是另一条产品线，会污染对照）。
